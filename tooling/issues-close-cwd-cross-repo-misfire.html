カテゴリ: tooling medium 実体験 pnpm gh issue-cmd platform

症状

fluxion リポで cd flipslidersand/fluxion && pnpm issues:close --issue=47 を実行したところ、 fluxion#47 ではなく dev-nodee-infrastructure#47（無関係な別 Issue・クローズ済み）に 完了コメントが投稿された。

原因

pnpm issues:close は Platform ルートの package.json スクリプト （node scripts/issue-cmd.mjs）に解決され、pnpm がスクリプトをルートで実行するため cwd のリポ情報が使われず、既定リポ（Platform）の Issue 番号に対して操作される。

解決策

  • 誤爆コメントは gh api -X DELETE repos/<owner>/<repo>/issues/comments/<id> で削除
  • 外部リポの Issue クローズは Closes #N を PR に書いてマージ時 auto-close に任せる、 または gh issue close N --repo owner/repo を直接使う

予防

  • pnpm issues:start/close は Platform リポの Issue 専用と覚える
  • 他リポでは使わない。改善するなら issue-cmd.mjs に --repo オプション or cwd の git remote から対象リポを自動検出する機能を追加する（Issue 化済み）

関連するエラー

  • "gh issue create でラベルが存在しない場合 Issue 自体も作成されない"
  • "pnpm install が親の pnpm-workspace.yaml に引っ張られてサブディレクトリで正しく動かない"
  • "pnpm workspace 未登録サブディレクトリで install が効かない"
